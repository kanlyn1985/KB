## 目标
对 agent_kb_core 实施"ontology 驱动"升级，并用真实文档（CCU 需求规格书、GB/T 18487.1-2023、QC/T 1036）验证入库质量与召回质量，量化与 RAG 的区别。按已确认的 10 项决策执行：结构化优先、轻量 is-a、注册表式关系+方向遍历、属性 schema+确定性解析、Schema 离线 LLM 候选+人审/实例层确定性/运行时无 LLM、graph 权重 ≥1.0/vector 可选/结构化命中占比 ≥80%、查询结构化槽位先单跳、ContextPack 主输出+服务层可选生成、聚焦 obc_dcdc 领域、先基线后升级对比。

## 阶段 A：基线验证（不改 agent_kb_core 代码）

1. **环境准备**：用 `/usr/bin/python3`（3.12.3）+ `PYTHONPATH=agent_kb_core/src` 运行（agent_kb_core 零依赖）。PDF 文本提取用 PyMuPDF（.venv-paddle site-packages 已有）。确认 `import agent_kb` 可用。
2. **文档转文本**：把 `knowledge_base/raw/` 中 3 份目标文档转成 UTF-8 文本：DOC-000015（CCU 需求规格书）、DOC-000003（GB/T 18487.1-2023）、DOC-000001（QC/T 1036，扫描件——优先复用旧管线 `knowledge_base/normalized/DOC-000001*.json` 的 ocr_markdown 产物，不可用则跳过并在报告中注明）。输出到 `agent_kb_core/validation/texts/`。
3. **批量入库**：新建验证脚本 `agent_kb_core/validation/batch_index.py`，循环调用 `compile_text_to_production_store`（每文档一个 logical-document-id + version-label v1），入库到 `agent_kb_core/validation/baseline.sqlite3`（不污染现有 agent-kb.sqlite3），domain 用现有 obc_dcdc pack。脚本用 argparse + 纯 stdlib。
4. **入库质量基线**：`agent_kb_core/validation/ingestion_report.py` 统计每文档：evidence 块数/平均长度/空块率、source unit 分类分布、facts 数与置信度分布、对象投影数（seed vs candidate）、术语覆盖率（DomainPack 别名在文本中的命中）、图边数、FTS/向量行数。输出 JSON + Markdown 表。
5. **召回质量基线**：`agent_kb_core/validation/build_golden_cases.py` 从入库 facts/objects 程序化生成 golden cases（query→expected_object_ids/fact_ids/evidence_ids，分四类：术语查询/类型查询/值域查询/关系查询），写入 `golden_cases.json`；随后人工抽查修正 10-20 条（记录修正 diff）。`agent_kb_core/validation/retrieval_report.py` 用 `SQLiteKnowledgeStore.load_index_view()` + `evaluate_retrieval()` 对多文档库评测，输出 Hit@K/MRR/object/card/fact/evidence recall + 各通道命中归因（解析 RetrievalResult.diagnostics）。
6. **基线报告**：`docs/validation/BASELINE_REPORT.md`——记录现状问题（预期：术语覆盖率低、graph 边≈0、值域/关系查询无法命中、结构化命中占比低）。

## 阶段 B：ontology 化实施（修改 agent_kb_core）

1. **DomainPack schema 升级**（`src/agent_kb/domains/schema.py` + obc_dcdc JSON）：
   - object_types 增加 `parent` 字段（轻量 is-a）；core 提供类型提升解析（子类型对象可满足父类型查询目标）
   - relation_types 升级注册表：`name/category(structural/referential/attributive/temporal)/inverse_name/undirected/source_type/target_type`
   - properties 升级：属性名/值类型(number/range/string/reference)/单位
2. **类层次解析**：`projection/projector.py` 投影时解析类型层级；`query/understanding.py` 的 `_link_target_objects` 支持按类型匹配（含子类型）。
3. **关系抽取增强**：`graph/extraction.py` 的 DeterministicRelationExtractor 注册表驱动——按 relation_types 方向/inverse 物化边，属性 reference 值命中对象时生成属性边；仍不推断隐藏因果。
4. **属性值解析器**：新增 `core/attributes.py`（或并入 facts.py）——确定性 value parser（number/range/string/reference + 单位容差，复用 kb1_ontology range_parser 的 "50 ± 10 ms" 解析思路，不搬代码）；解析结果结构化写入 `Fact.payload` 与 `ObjectProjection.properties`（schema 加 v9 迁移或 payload 内嵌，遵循 additive 迁移原则）。
5. **查询理解升级**：`query/understanding.py` 的 QueryFrame 增加结构化槽位：`object_type`（类型提升）、`attribute_filter`（属性名+值+比较符）、`relation_path`（单跳方向，支持 inverse）。多跳分解器留待下一阶段。
6. **通道权重**：`retrieval/engine.py` graph 通道权重升至 ≥1.0（与 lexical 平级）；`retrieval/production.py` 同步；vector 标注为可选 provider（默认仍 HashEmbedding 合同基线）。
7. **Schema 内容扩充**：用 LLM 离线生成 obc_dcdc 领域定义候选（从 3 份文档提取：术语/对象类型/关系/属性），输出候选 JSON 供人工 review；review 通过后写入 `agent_kb_core/domains/obc_dcdc/*.json`，候选与审查记录保存于 `docs/ontology/obc_dcdc_expansion/`。
8. **测试**：新增/更新单测——domain schema 升级、类型提升、属性解析器（含 "50±10ms" 类用例）、方向遍历、结构化槽位查询；运行 `pytest`（若系统无 pytest，用 stdlib unittest 兼容或安装到 venv）。

## 阶段 C：升级后验证与对比

1. 同 3 份文档重新入库到 `agent_kb_core/validation/ontology.sqlite3`（同 batch_index.py，domain 用扩充后 pack）。
2. 同 golden_cases.json 重跑评测（含人工修正后的 case 集），并新增值域查询/关系查询 case 覆盖新能力。
3. **对比报告** `docs/validation/ONTOLOGY_VALIDATION_REPORT.md`：基线 vs 升级后——术语覆盖率、对象投影数、图边数、属性解析率、结构化通道命中占比、Hit@K/MRR、值域查询准确率、关系查询准确率；给出"与 RAG 区别"的量化结论（结构化命中占比是否 ≥80%）。
4. 验证结论进入 `agent_kb_core/docs/`（如 STATUS 更新或新 PHASE_10 文档草稿，不强制）。

## 交付物
- 脚本：`agent_kb_core/validation/`（batch_index / ingestion_report / build_golden_cases / retrieval_report）
- 数据：baseline.sqlite3、ontology.sqlite3、texts/、golden_cases.json
- 报告：docs/validation/BASELINE_REPORT.md、ONTOLOGY_VALIDATION_REPORT.md
- 代码：agent_kb_core 的 DomainPack schema、属性解析、关系抽取、查询槽位、权重调整（含单测）
- DomainPack：obc_dcdc 扩充后 JSON + 候选/审查记录

## 风险与对策
- QC/T 1036 扫描件 OCR：优先复用旧管线产物，不可用则跳过并注明
- 系统无 pytest：验证脚本用纯 stdlib；单测兼容 unittest 或安装 pytest
- .venv-paddle shebang 损坏：只用其 site-packages 的 PyMuPDF（PYTHONPATH 引用），不依赖 venv 激活
- 权重调整可能影响现有 Phase 4 测试断言：同步更新测试并以"结构化命中占比"新指标为准
