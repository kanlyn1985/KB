# V0.6 Design — Graph-aware Deterministic Reasoning Layer

- Document ID: AKB-DD-V06-001 · Version: V1.0 · Status: DESIGN BASELINE（待评审）
- 基线：V0.5 FINAL / FROZEN（e7a286e）· V0.5 design f5e28dd（frozen，零修改）
- 性质：DESIGN ONLY——零 runtime/零 migration/零 V0.5 触碰

## 1. V0.6 核心 Capability（决策）

**V0.6 PRIMARY CAPABILITY = Graph-aware deterministic reasoning orchestration
（图上下文感知的确定性推理编排）。**

### 1.1 为什么是它（§6 候选逐项裁定）

| 候选 | 裁定 | 理由 |
|---|---|---|
| A Graph Reasoning | **SELECTED** | V0.5 Query 只回答"图中有什么"（retrieval）；
  从 validated graph 结构化上下文产生新 candidate 是 Query 无法完成的
  interpretation+inference 组合；V0.4 ReasoningEngine 已有 candidate/governance/
  provenance 机制但输入面是**显式 parent id 列表**（engine.reason(parent_ids)）——
  缺"从图上下文自动选择输入"的编排层 |
| B Evidence Synthesis | REJECTED（已有） | V0.3 synthesis 已实现多证据合成并冻结；
  再做属重复建设 |
| C Conflict Resolution | REJECTED（Governance/Temporal 域） | V0.3 conflict resolution +
  V0.4 RR-04 __DISPUTED__ 旗标已覆盖"标记不裁决"；裁决属治理（human），非推理 |
| D Hypothesis Generation | DEFERRED→V0.7+ | 需要独立 hypothesis 生命周期（候选≠推理
  ≠假设）；V0.6 先补齐推理编排地基 |
| E Planning/Decision | REJECTED for V0.6 | 行动/计划需 agent runtime + 副作用边界，
  与确定性可审计目标冲突 |

### 1.2 为什么 V0.5 Query Layer 不能完成（五层边界，§5）

```text
retrieval      = "图里有什么" —— V0.5 Query（frozen：Q-01..06，只读确定性）
interpretation = "这些事实如何组织/归一" —— V0.5 projection + identity（frozen）
inference      = "由事实按规则推出什么候选" —— V0.4 ReasoningEngine（已有，
                 但输入=显式 parents）+ V0.6 新增编排（输入=graph context）
hypothesis     = "超出规则的待验证猜想" —— V0.7+（新生命周期）
decision       = "基于知识采取行动" —— V0.8+/agent 层（禁止 V0.6 触碰）
```

关键区分：inference 的输出是 **InferenceCandidate（候选）**，经过 governance 才可能
成为 Assertion——V0.6 全程不产生"新事实"。

## 2. V0.4 → V0.5 → V0.6 三层关系（以实际代码为准修正）

实际代码核验（engine.py/builtin_rules.py/query.py/persistence.py）：

- **V0.4 = deterministic assertion-level reasoning foundation**：ReasoningEngine
  输入是显式 `parent_ids` 列表 → _load_parents → provider.infer → 提案校验/深度/环
  → create_candidate（inferred）→ ReasoningRun 持久化（migration 14）。**已承担：
  candidate 生命周期、run 记录、fingerprint 幂等、governance 边界（inferred→asserted
  禁令）**。不承担：图上下文选择、跨实体模式匹配输入组装。
- **V0.5 = validated graph projection**：只读（Q-01..06）+ 持久化（kg_*）+
  provenance 回溯。**零推理职责**（V0.5 FINAL scope audit 已确认）。
- **V0.6 = graph-context-aware reasoning orchestration**（新增）：
  `GraphReasoningContextBuilder`（从 kg_* 选择输入子图）→ 组装 V0.4
  ReasoningEngine 调用 → candidate 输出带完整 context 引用。

**单一 ReasoningEngine 原则**：V0.6 **不新建第二个推理引擎**——复用 V0.4
ReasoningEngine/provider/candidate/governance 全链；V0.6 只加"上下文构建 +
编排"前置层。RR-01..04 规则语义 frozen（V0.4），V0.6 新规则走 provider 通道
（rule_version 组合 domain_pack_version——§6 DomainPack 边界）。

```text
V0.4 ReasoningEngine（candidate 生命周期/幂等/governance 边界）
        ↑ 复用（不重建）
V0.6 GraphReasoningContextBuilder + Orchestrator（图上下文 → parents 组装）
        ↑ 消费（只读）
V0.5 Validated Graph（kg_* 只读 Q-01..06）
```

## 3. 核心概念（§9 概念模型）

### 3.1 ReasoningContext（图级推理上下文）

```text
context_id        = "grc_" + SHA256(canonical_json({...})).hexdigest()[:16]
                    输入={root_entity, graph_fingerprint, status_filter,
                          temporal_context, query_constraints, rule_set_version,
                          max_hops, max_depth}
                    ——deterministic；同输入同 context_id
root_entity       = EntityNode.node_id（推理起点）
input_nodes       = 选中 kg_nodes（node_id 列表，canonical 排序）
input_assertions  = 选中 akb_assertions（assertion_id 列表——最终推理输入）
input_edges       = 选中 kg_edges（edge_id 列表，含边语义）
temporal_context  = V0.3 temporal scope 只读引用（不重算）
status_filter     = {"valid","flagged"}（Q-05 默认面；invalidated 仅 audit 显式）
query_constraints = hop/depth/谓词白名单/规则白名单
graph_fingerprint = 输入子图来源的 kg_projection_runs.fingerprint（V0.5 锚复用）
```

### 3.2 ReasoningRule（versioned contract）

```text
rule_id / rule_version        ——版本化；语义变更必须换版本（禁止隐式改）
rule_type                     = "deduction" | "transitive" | "corroboration" |
                                "contradiction_flag" | "domain_<id>"（DomainPack 实例化）
input_pattern                 = 断言形态谓词模板（如 RR-02 的 before 链形态）
output_pattern                = 候选形态
constraints                   = 前提状态要求/时间窗要求/最大展开数
实现载体                       = V0.4 ReasonerProvider 通道（RR-01..04 frozen 语义复用；
                                新规则 = 新 provider/rule_version，不改 frozen 语义）
```

### 3.3 InferenceCandidate（候选 ≠ 事实）

```text
candidate_id        = "gic_" + SHA256(canonical_json({conclusion, rule_id,
                      rule_version, parent_assertions, context_id}))[:16]
conclusion          = (subject_ref, predicate_ref, object) 形态
rule_id/rule_version
parent_assertions   = 依据断言（完整列表）
context_id          → ReasoningContext（可回溯输入子图）
confidence          = 确定性聚合（延续 V0.4 rule_weight×parent mean 约定）；
                      语义 = 规则强度度量，非概率真值
certainty_semantics = "deterministic_rule_derived"
provenance          = context_id → graph fingerprint → akb_assertions → akb_evidence
                      → akb_documents（§13 完整链）
status              = "inferred_candidate"（candidate 生命周期归 V0.4 机制管理）
```

**红线**：Candidate 永不直接成为 Assertion/事实；入库走 V0.4 create_candidate
（inferred）→ 治理 → validated（V0.4 既有路径）。

### 3.4 ReasoningRun / ReasoningResult

- ReasoningRun：延续 V0.4 akb_reasoning_runs（复用，零新表——§25 migration 判断）；
  V0.6 扩展字段经 derivation_json 携带 context_id/graph_fingerprint
  （JSON 内扩展，不改表结构）；
- ReasoningResult = {run_id, context_id, candidates[], warnings[], errors[],
  fingerprint}——与 V0.4 reason() 返回面同构。

## 4. Status Semantics（§10 状态转换矩阵）

| 状态 | 可参与推理（作输入） | 可产生的输出 | 禁止 |
|---|---|---|---|
| validated | ✓（primary 输入） | — | — |
| candidate | ✓（默认面，Q-05） | — | — |
| inferred | ✓（链式推理输入，深度受控） | 保持 candidate | inferred→asserted（V0.4 禁令延续） |
| disputed (flagged) | ✓（带 flag 参与但输出候选强制 flagged 语义标注） | flagged 候选 | 静默当 valid 用 |
| rejected/deprecated (invalidated) | ✗（默认排除；audit 模式显式时输出也标 invalidated 来源） | — | 作为推理前提 |
| hypothesized | ✗（不是 assertion status；V0.5 已排除出图） | — | 进入图推理输入 |
| hypothesis（V0.7+ 概念） | — | — | hypothesis ≠ inference ≠ assertion |

关键不变量：**inferred ≠ validated；hypothesis ≠ inference；inferred→asserted
仍然禁止**（除非 V0.4 既有 governance transition——human-actor）。

## 5. 边语义参与推理的裁定（§11）

| 边 | 参与推理？ | 裁定 |
|---|---|---|
| supports | ✓ 作为规则前提（前提必须 ≥1 evidence 支撑——V0.4 INV-001 语义自然衔接）；
  但 "A supports B" 本身不构成 B 为真——前提是 **B 及其 supports 的 evidence 集合** | 是（带 evidence 门） |
| relates_to | ✓ 关系推理主通道（实体间谓词边——RR 规则的模式匹配面） | 是（primary） |
| derived_from | ✓ 链式推理通道（祖先断言可作后续推理输入——深度受控） | 是（深度受控） |
| contradicts | **否**——V0.5 明确 contradicts = ConflictRecord 投影，**不是逻辑否定**；
  V0.6 不得升级它。矛盾信息只作为 context 标注（候选输出强制 flagged 语义） | 否（仅 context 标注） |
| validates | 否——治理动作投影，非知识语义 | 否 |
| extracted_from | 否——抽取谱系，非推理语义（provenance 用） | 否 |

## 6. Temporal Reasoning（§12 继承 V0.3）

- temporal_context 只读引用 V0.3 temporal scope（不重算/不改写六态）；
- 规则前提匹配必须带时间窗检查：A(T1) 与 B(T2) 的关系判定在规则 input_pattern
  中显式声明 temporal 约束；**A(T1)≠B(T2) 不自动构成 contradiction**——
  时间不相交/相邻的断言差异由 V0.3 temporal semantics 解释；
- 时间模糊（temporal ambiguity）= fail-closed 条件之一（§16）。

## 7. Provenance Contract（§13）

```text
InferenceCandidate
  ↓ context_id
ReasoningContext（graph_fingerprint → kg_projection_runs）
  ↓ input_assertions
akb_assertions（parent 断言）
  ↓ evidence_refs
akb_evidence → akb_documents
  ↓ rule 引用
rule_id + rule_version（+ domain_pack_version）
```

"你为什么得到这个结果？" = conclusion + rule_id/version + context_id（可展开整个
输入子图）+ parent_assertions。零不可追溯输出——任何缺级 = fail-closed。

## 8. Determinism / Idempotency（§14/§15）

- 同（graph state + rule_version + context 定义）→ 同 candidate set；
- context_id 与 candidate_id 均确定性派生（canonical JSON）；
- fingerprint 策略：run fingerprint = SHA256(canonical_json({context_id,
  rule_set_version, provider rule_version, parent_assertions sorted}))——
  延续 V0.4 reasoning_fingerprint 语义；
- 禁止依赖：DB 行序/哈希迭代序/随机/时钟/网络/LLM——**deterministic first**；
- 幂等：同 fingerprint 重放 → 同 run 命中（V0.4 机制复用）。

## 9. Failure Semantics（§16 fail-closed 清单）

| 条件 | 处置 |
|---|---|
| missing assertion / missing provenance | error（run failed，零候选） |
| invalid node/edge type | error |
| unsupported status（invalidated 作前提） | error |
| rule version missing | error |
| context incomplete（root 无邻域/约束矛盾） | error |
| temporal ambiguity | error |
| entity ambiguity（identity 冲突未治理） | error（转治理，不自动消歧） |
| cycle | 检测 + 截断 + warning（V0.4 环语义延续） |
| depth overflow / candidate explosion | depth>max → skip+warning；候选数超限 → run partial |

## 10. Depth / Cycle Control（§17 独立定义）

- **reasoning depth ≠ query depth**：Q-04 的 8 是读取遍历上限；V0.6 推理深度
  独立定义为 **max_derivation_depth = 4**（每层规则展开 = 一次推理跳）——
  理由：推理深度增长是候选组合爆炸来源（每跳候选数乘性增长），
  4 层在 64-seed 规模内可控且覆盖 RR-01..04 全部可达模式；
- cycle：visited-set（assertion_id 集）+ 环截断 warning（V0.4 语义延续）；
- rule expansion limit：单 run 单规则展开 ≤ 256 候选；
- candidate explosion control：全 run 候选 ≤ 1024，超限 → partial + warning。

## 11. Governance Boundary（§18）

```text
Reasoning（V0.6/V0.4）→ InferenceCandidate（inferred/candidate）
                          ↓ governance（human-actor，V0.4 机制）
                       validated
```

- Reasoning 只产 candidate；不 validate/approve/promote/merge——零新治理动作；
- inferred→asserted 仍永久禁止（V0.4 硬门延续）；
- V0.5 EntityGovernanceService 边界不变（merge/split/alias 仍 human-only）。

## 12. LLM Boundary（§19）

- **LLM 非正确性必需**——V0.6 全部能力在 deterministic reasoner 上完整；
- 未来 LLM = proposal/interpretation 通道：输出只能作为 candidate（同 governance
  边界），永不成为 source of truth / validation authority；
- LLM 输出必须携带独立 provenance（provider/model/prompt 版本），且
  **nondeterministic 输出单独治理**（不在 V0.6 范围）。

## 13. DomainPack 边界（§21）

| Owner | 拥有 |
|---|---|
| DomainPack | 词汇（entity types/predicates）、领域规则**实例化参数**、
  validation constraints（只收紧） |
| Reasoner | 规则**执行语义**（RR 通道）、候选生成 |
| Graph | 结构事实（六类节点/六类边，frozen） |
| Governance | 状态裁决（human）——唯一的 validate/reject/merge 权威 |

规则语义单一归属：DomainPack 只实例化参数（谓词映射/约束），不定义新推理语义；
避免三处重复定义业务语义。

## 14. Migration Impact（§25）

**NO MIGRATION（决策）**：V0.6 复用 V0.4 akb_reasoning_runs（derivation_json 内扩展
context_id/graph_fingerprint——JSON 字段，不改表）+ V0.5 kg_*（只读）+ akb_provenance
（graph:reason-* 活动复用现有机制）。若实现期发现 JSON 扩展不够（如需 context 索引），
属实现期任务书决策点，设计期不预加。

## 15. Future Boundary（§20）

V0.6 不实现：V0.7+ hypothesis 生命周期、planning/decision、agent execution、
LLM autonomous reasoning、分布式图、外部图 DB、向量检索。预留接口边界：
provider 通道天然支持新 reasoner 类型；context/candidate 的 canonical JSON 结构
可扩展字段（新增字段不破坏旧 fingerprint 语义需 rule_version 递增）。
