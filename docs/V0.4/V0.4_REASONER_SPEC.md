# V0.4 Reasoner Spec — Reasoning / Inference Layer

- Document ID: AKB-DD-V04-001 · Version: V1.0 · Status: Design Baseline（DESIGN READY 待评审）
- 上游基线：V0.3 FINAL — ACCEPTED / FROZEN · V0.2 RELEASE BASELINE · V0.1 ACCEPTED
- 约束：本文档为设计——不修改 V0.3 frozen code；不改 temporal semantics；不动 INV-001..010
  与 V03-INV-001..006。

## 1. 定位

V0.3 在 candidate 产物上显式预留了 `assertion_type=inferred` 通道：
- V0.2 create_candidate 校验：inferred 必带 derivation{rule_ref/parent_assertions/reasoner_id}，
  否则拒绝（E-CANDIDATE-BUILD-FAILED / E-ILLEGAL-TRANSITION 语义）；
- State Machine：inferred 不得晋升 asserted（→ validated 允许且仅人工治理可 asserted）；
- V0.3 合成显式排除 inferred（S-07："inferred 保留给 reasoner 通道——V0.4"）。

V0.4 = 在该预留位上建立**受治理的推理层**：从既有 Candidate/Validated assertions
（+ SemanticUnit 上下文）出发，经规则推理产生**新的 inferred candidate assertions**，
携带完整 derivation chain 与 reasoner provenance。

## 2. 核心原则（不可违反）

R-01 **inferred ≠ authoritative**：inferred 断言恒为 candidate；晋升路径与既有治理一致
（inferred → validated 仅人工；**inferred → asserted 被 State Machine 永久禁止**——
如需 asserted 必须先有独立 extracted/observed 证据支撑并重新分类）；
R-02 **derivation completeness**：每个 inferred candidate 必带
{rule_ref, parent_assertions[], reasoner_id, rule_input_snapshot}——缺任一即拒绝（继承 INV-002）；
R-03 **parent 边界**：parent_assertions 只能引用既有 candidate/validated 断言
（不得引用 inferred 自身产物作为直接 parent 的链式自举——一阶推理限定：inferred 的 parent
必须是非 inferred 或更早 run 的 inferred，环检测强制）；
R-04 **provider neutrality**：ReasonerProvider Protocol 同 V0.2/V0.3 先例——内置规则引擎
（strict deterministic）与外部/LLM reasoner（stochastic but traceable）双模式；
R-05 **evidence gate**：inferred candidate 的 evidence_refs = parent 断言的 evidence_refs
并集（溯源到最终 Evidence——INV-004 跨层保持）；
R-06 **无动作/无自主晋升**：推理层不触发外部动作（INV-010）、不自动晋升（INV-009/002）、
不修改 Evidence/authoritative（INV-005/002）。

## 3. ReasonerProvider 接口（Protocol，V0.2/V0.3 同款风格）

```python
class ReasonerProvider(Protocol):
    def reasoner_id(self) -> str: ...
    def rule_version(self) -> str: ...
    def infer(
        self,
        parent_assertions: list[KnowledgeAssertion],
        context: ReasoningContext,          # domain_pack/ontology 范围/规则参数
    ) -> list[InferredProposal]:            # 结构化提案（未落库）
        ...
```

- 内置默认：`BuiltinRuleReasoner`（strict deterministic；规则集 R-01..R-0n 版本化）；
- 外部/LLM：stochastic but traceable（provider metadata 全记录）；
- Provider 输出必须过 schema validation（InferredProposal.validate）——malformed → 拒绝；
- Provider **不得**接触 create_candidate/治理 API（与 V0.2/V0.3 边界一致——落库由
  ReasoningEngine 编排层执行）。

## 4. InferredProposal（提案 schema）

```text
InferredProposal:
    proposal_id: str            # run 内稳定编号 inf_0001…
    subject_ref / predicate_ref / object     # 断言三元（同 KnowledgeAssertion 语义）
    assertion_type: "inferred"  # 恒定
    derivation:
        rule_ref: str           # 规则编号（rule_id@rule_version）
        parent_assertions: [assertion_id, ...]   # R-03 边界
        reasoner_id: str
        rule_input_snapshot: CanonicalJSON   # 输入断言的 canonical 摘要（审计回放）
        confidence_basis: {parent confidences + rule weight}
    confidence: float           # round 4（继承确定性约定）
```

## 5. 推理规则集（BuiltinRuleReasoner V1，最小核心）

| 规则 | 输入 | 输出 | 语义 |
|---|---|---|---|
| RR-01 Deduction | parent: (A satisfies RuleX), (RuleX requires B) | (A requires B) inferred | 规则展开 |
| RR-02 Transitive Closure | (A before B), (B before C) | (A before C) inferred | 时序传递（复用 V0.3 TS-02 时序候选） |
| RR-03 Same-value Corroboration | 多 parent 同 (subj,pred) 同值 | 合并候选（置信加权） | 佐证聚合 |
| RR-04 Contradiction Flag | parent 同 (subj,pred) 异值 | inferred dispute 候选（供治理） | 矛盾显式化（不裁决） |

规则表版本化（rule_set=v04-rules-v1）；全部 strict deterministic；规则扩展走配置/版本发布。

## 6. ReasoningEngine（编排，与 V0.2 compiler/V0.3 synthesizer 同构）

```text
ReasoningRun（canonical 表 akb_reasoning_runs，migration 14 设计——本文档只设计）
    ↓ parent selection（候选池：candidate/validated；环检测）
    ↓ ReasonerProvider.infer（提案生成）
    ↓ schema validation + derivation completeness 校验（R-02）
    ↓ create_candidate(assertion_type="inferred", derivation=...)（唯一边界——继承）
    ↓ Provenance(activity=infer) + 五级链（Candidate→Run→Parents→…→Evidence/Document）
```

- 幂等：ReasoningFingerprint = SHA256(CanonicalJSON({parent_assertion_ids sorted,
  reasoner_id, rule_version, configuration_hash}))——同指纹重放返回既有 run（V0.3 锚模式）；
- 事务：per-run SAVEPOINT 原子；
- 失败隔离：提案级失败丢弃+warning；run 级失败回滚留审计。

## 7. 生命周期（inferred assertion）

```text
creation（ReasoningEngine，恒 candidate）
    → 治理：candidate → validated（仅人工/validator；须引用独立证据）
    → inferred → asserted = **永久禁止**（State Machine）
    → disputed/deprecated 路径与既有治理一致
```

## 8. 与既有层的关系

| 层 | 关系 |
|---|---|
| V0.2 compilation | 只读消费其产物作为间接上下文；零改动 |
| V0.3 synthesis | parent 池包含 synthesis 产物；零改动；S-07 预留位兑现 |
| V0.1 governance | create_candidate 唯一边界；状态机/triggers 原样 |
| Agent Runtime | 零新增写路径；推理可被 agent 触发但产物仍是 candidate |
