# V0.12 Design — Knowledge Analytics Layer

- Document ID: AKB-DD-V12-001 · Version: V1.0 · Status: DESIGN BASELINE（待评审）
- 基线：V0.11 FROZEN（cdec78e）· V0.11 design 2e89a4f（frozen）· V0.10 FROZEN（52ce55c）·
  V0.9 FROZEN（88ea3bd）· V0.8 FROZEN（0e49c3d）
- 性质：DESIGN ONLY——零代码/零 migration 实施/零测试修改/零 frozen 触碰
- **主问题回答**：七层栈（Fact→Reasoning→Evolution→Causal Projection→Health
  Governance→Persistence→Maintenance Proposal）之后缺失的下一个语义抽象是
  ——**跨层语义聚合的"理解层"**：系统已能存事实、推理、追踪演化、观察因果、
  检测健康/冲突、持久化治理信号、生成 human 提案——但所有这些能力都是
  **单对象/单时点视角**。缺失的是把七层产物聚合成**知识库级演化理解**的能力：
  知识漂移了多快？治理效率如何？因果覆盖是否在改善？——Knowledge Analytics
  Layer（观察 only）。

## 1. Capability Gap Analysis（V0.11 为什么不够）

V0.11 交付治理闭环（检测→提案→human 裁决）。缺口：

1. **无跨时点视角**：health/conflict/proposal 信号均已持久化（V0.10/0.11），
   但只有逐条查询——没有"本月知识漂移 vs 上月"的时序聚合，也没有
   "提案→裁决→知识变化"的端到端效率度量；
2. **治理质量不可度量**：提案是否被及时裁决？哪类信号产生的提案裁决率高？
   governance 每阶段（V0.4→V0.11）各自有审计，但无人回答"governance 效率"；
3. **因果覆盖不可追踪**：V0.9 有 causal_coverage 单点信号，但"覆盖随演化
   增长/衰退"的趋势面缺失；
4. **前置数据全部就绪**：akb_health_signals（V0.10 持久化+时序查询）、
   akb_conflict_records、V0.8 task/verdict 审计、V0.11 proposal 审计——
   Analytics 只需**只读聚合**，零新数据生产；
5. **A/B 候选的前置仍未满足**：counterfactual 需机制比对 level-2+、mechanism
   需 ontology 冻结——两前置在 V0.11 结束时仍未发生。

**结论**：下一层抽象是 Knowledge Analytics Layer（Candidate C）——它是唯一
"全部前置就绪 + 零新风险面 + 补齐理解层"的候选；且它是 V0.11 P2 遗留项
（提案-裁决关联分析）的正式化。

## 3. Architecture Boundary

```text
New Layer Name: Knowledge Analytics Layer（观察/理解层——第八层）

Responsibilities:
  1. 时序聚合：health/conflict/proposal 信号的历史趋势（漂移/衰退/密度）
  2. 治理效率度量：proposal→task→verdict 端到端时延与裁决率（按信号类型分组）
  3. 因果覆盖追踪：causal edge 密度/覆盖目标随快照序列的趋势
  4. 知识增长度量：assertion/graph 对象计数随 migration 时序的趋势
  —— 全部只读聚合；输出 MetricReport（fingerprint 锚）

Inputs（只读消费——零新数据生产）:
  akb_health_signals / akb_conflict_records（V0.10）
  akb_provenance 全活动面（V0.4..V0.11 审计）
  akb_causal_edges 持久投影 + V0.8/0.9 identity 面（只读）

Outputs:
  KnowledgeMetricReport（immutable；fingerprint；provenance 锚）
  —— 报告对象 + graph:analytics-report-create 审计；无任何写回

CAN do:
  聚合/排序/时序对比/趋势计算（确定性纯函数）；产出报告与视图

MUST NEVER do:
  自动 correction/maintenance（触发了也只读报告）· truth arbitration ·
  修改任何 frozen 面行为 · 把度量变成学习信号 · 删除/改写历史审计
```

## 4. Data Flow Design

```text
七层 frozen 产物（信号/审计/投影——全部只读）
        |
        v
V0.12 KnowledgeAnalyticsRuntime（确定性聚合——纯函数）
        |
        v
KnowledgeMetricReport（immutable + fingerprint + 审计）
        |
        v
Existing governance flow（human 阅读 report → 决定是否发起 V0.11 proposal）
```

三不变量延续：**Observation ≠ Truth**（报告是观察不是事实——零 assertion
写入）；**Proposal ≠ Decision**（报告可建议发起提案，但提案仍走 V0.11
human-first 通道）；**Human = Final authority**（报告供 human 阅读，零自动
行动）。

## 6. Migration Analysis

**Migration: NO**——报告为**即时聚合产物**（同状态同报告，可随时重算），
payload 走 akb_provenance metadata（graph:analytics-report-create，V0.11
registry snapshot 同模式先例——摘要级 payload）；信号/审计数据面已持久化
（migration 16/17）。**migration 19 触发条件记录**：①报告需要跨快照结构化
对比查询（非重算）②metrics 时序需要独立索引面。

## 7. Frozen Boundary

V0.5..V0.11 全部 immutable 零修改。**未来扩展点识别**（仅记录，不在 V0.12
实现）：①metrics 白名单扩展（新指标=新任务书）②counterfactual/mechanism
（ontology 冻结后）③analytics→proposal 的"建议发起"界面（仍 human-first）。

## 8. P0/P1/P2

### P0（触发即 STOP）
- analytics 写任何 frozen 面（assertions/kg_*/信号表/hypothesis 状态）；
- 报告成为自动 action 触发器（报告→自动 proposal/自动 maintenance）；
- identity 引入 timestamp/random；
- 把 human decisions 用作学习信号（Governance Feedback 红线）。

### P1（实现期必须解决）
- 窗口语义定标（时序窗口按 occurred_at——秒级精度下的同秒 tie 处理）；
- metrics 计算的确定性（JOIN 面浮点聚合——round 策略与 canonical 排序锁定）；
- payload 尺寸（大基数聚合结果超 metadata 实用上限时按 V0.10 先例记录
  migration 19 触发）。

### P2（future optimization）
- cursor 降采样 / 报告 diff 视图 / metrics 白名单扩展 / 可视化导出。
