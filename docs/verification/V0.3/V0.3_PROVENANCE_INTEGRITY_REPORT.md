## 1. Defect Description

ONTOLOGY_CONFLICT（CONF-002）与 IDENTITY_CONFLICT（CONF-005）的 ConflictRecord.unit_ids
被赋值为 candidate_id（`unit_ids ← candidate_id`），违反 provenance contract：
source_evidence_ids=evidence_id / unit_ids=unit_id / candidate_id 仅允许出现在
sides 细粒度 provenance——三者不得混淆。另 CONF-006-STATE 经 relation clusters 间接
反推 unit ownership（结构脆弱）。

## 2. Root Cause

初版 conflicts.py 以复制粘贴方式手工构造各冲突的字段——entity 簇 members 既有
candidate_id 又有 unit_id，编写时误取 candidate_id；无统一生成路径导致同类错误
在不同冲突类型间复制扩散；state contradiction 的 sides 初版未自带 unit_id，
迫使 ConflictDetector 反查 relation clusters。

## 3. Code Repair

conflicts.py 重写为统一契约：
- 新增 `_provenance_from_members(members) -> (source_evidence_ids, unit_ids)`——
  全部 7 类冲突经此生成 provenance（消除手工构造）；
- CONF-002/CONF-005 的 unit_ids 修复为真实 unit_id；
- CONF-003/004 改用显式 (evidence_id → unit_id) 语义索引（units_of）；
- CONF-006-STATE：state contradiction 现自带 members/sides 的 evidence_id+unit_id
  （alignment._state_alignment 生成 sides 时内嵌 unit_id），ConflictDetector 直接
  消费——**删除 relation clusters 间接反推**；
- 规则编号定案：RELATION_CONFLICT=CONF-007-RELATION（原 CONF-006 与
  CONF-006-STATE 前缀易混；读取方按 CONF-006* 前缀判断的兼容性不受影响）；
- 清理 CONF-002 残留死代码（`for m2 in [m] if True`）。

```text

                      不得冒充 unit_ids

                      CONF-003 TEMPORAL / CONF-004 SOURCE / CONF-005 IDENTITY /
                      CONF-006-STATE / CONF-007-RELATION）
audit_timestamp     ← detect(audit_ts=...) 调用参数
provider_id         ← 参与 provider（builtin=None）
```
