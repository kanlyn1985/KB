## 1. Defect

TEMPORAL_CONFLICT 判定缺少 semantic context——"恰两证据全隔互斥窗"无实体上下文校验
即升级 contradictory，跨实体（Pump-A vs Valve-B）互斥窗会误产 TEMPORAL_CONFLICT；
无关节点可能渗入 contradiction_members。

## 2. Root Cause

初版实现以时间窗几何关系（disjoint/ordered 数量）单变量判定，未对齐设计六态表
contradictory 的定义"同实体同属性区间互斥"——缺少"同实体/同语义事实"上下文维度。

## 3. Design Reference（design wins）

- V0.3_TEMPORAL_SYNTHESIS_SPEC 六态表：contradictory = "同实体同属性区间互斥"；
  TS-02 sequential = "区间不相交且 A.before(B)（可合成时序候选）"；
  TS-03 contradictory 不合成转 ConflictDetector。
- V0.3_CONFLICT_SPEC：TEMPORAL_CONFLICT = valid_time contradictory / event_time 不一致
  AND 实体簇重叠。
- V0.3_ALIGNMENT_SPEC：state contradictory validity → STATE_CONFLICT 候选（state 侧
  矛盾由 STATE_CONFLICT 通道承担）。

## 4. Temporal Semantic Model（定案）

| 态 | 判定 |
|---|---|
| same | 同实体 + 窗完全等价 |
| overlapping | 同实体 + 窗相交非全隔链 |
| sequential | 3+ 方顺时链（TS-02 时序候选）或跨实体互斥窗（正常时序并存）|
| contradictory | **恰两证据 + 同实体簇上下文重叠 + 区间互斥**（同事实窗断言冲突，冲突显式化交治理）|
| missing | 无可靠时间 |
| unresolved | 有表达未解析 |

## 5. Semantic Context Rule

Temporal Comparison Context = evidence_id → 实体簇集合（unit 簇集合并集）。
互斥对必须 `_context_overlap(pair) == True`（双方实体簇交集 ≥1）才入
contradiction_members；entity_context 缺失/空簇 → 保守不制造冲突。
member canonical：unique_by (evidence_id, unit_id) + deterministic sorting。

## 6. Code Repair

- alignment.py：`_temporal_alignment(units, entity_context)`——pairwise 互斥检测
  （非仅相邻，修复 E1/E3 重叠夹隔 E1/E2 互斥的漏检）+ context 过滤 + canonical 去重；
  align() 主流程构建并传入 context；互斥对在 sequential/contradictory 两种 overall 下
  都记录（供 ConflictDetector/治理上下文）。
- 裁决（design wins + 冲突显式化原则）：恰两证据全隔互斥+同实体上下文 = contradictory
  （TEMPORAL_SPEC 六态表最小满足；冲突显式化优先于 TS-02 时序解读——治理可复核）；
  3+ 方顺时链 = sequential（TS-02）；跨实体互斥 = sequential（禁止跨实体制造冲突）。
  过程中记录一次设计内部张力（六态表 contradictory vs TS-02 sequential 对两证据
  全隔场景双标）——以冲突显式化原则消解，未改设计文档。
