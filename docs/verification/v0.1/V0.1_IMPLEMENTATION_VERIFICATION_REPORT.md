## 1. Production DB Isolation

- **原问题**：`test_answer_contract.py` 直接以生产库路径调用 `query_production_store`，
  而 `production_context.py`（:149/:206）打开 store 后防御性执行 `SchemaMigrator.migrate()`
  → 生产库在测试会话中被应用迁移 9/10（ADDITIVE：7 张空 akb_ 表 + 可空列，既有数据零改动）。
- **修复位置**：`test_answer_contract.py` —— session 级 fixture `isolated_db`
  将生产库复制到 pytest tmp（`shutil.copy2`），全部 7 项断言改跑副本；
  `query_production_store`/`compile_text_to_production_store` 的 migrate 行为保持不变（生产 CLI 正确语义）。
- **isolation mechanism**：副本吸收迁移副作用；生产库以只读方式被复制，测试会话零写入。
- **test evidence**：`test_production_db_isolation.py` —— 记录会话首查 SHA-256，
  会话尾校验不变（file hash 覆盖 schema+数据）；副本测试后生产库 migrations 行数不变（10）。
- **production DB before/after**：same file / same hash / same schema / same data ✅

## 2. Adversarial Governance Tests（test_governance_adversarial.py，9 项全过）

| 攻击路径 | 场景 | 结果 |
|---|---|---|
| 1 伪造完整链 | 直 SQL INSERT provenance+transitions+UPDATE status | **语义裁决**：DB 层强制状态对白名单/type 边界/provenance 一致性/append-only；actor 授权属应用层（SQLite 无认证主体）。持 DB 写权限者的伪造链会成功但**完整留痕**（append-only 审计行不可篡改，事后可追责）；API 层重放为幂等 no-op，进一步晋升仍受权限矩阵约束。残余风险：持 DB 写权限者=DBA 等价，由部署边界防护 |
| 1b 假 provenance | transitions 引用不存在的 provenance | 11.2 触发器 ABORT ✅ |
| 1c 非法状态对 | validated→candidate 伪造迁移行 | 11.1 白名单触发器 ABORT ✅ |
| 2 伪造 actor | system/llm 冒充 human promote | API 权限矩阵 E-ACTOR-NOT-AUTHORIZED ✅ |
| 2b type 边界（SQL 层） | inferred→asserted 伪造迁移行 | 11.1b type-boundary 触发器 ABORT ✅ |
| 2c hypothesized（SQL 层） | →validated 伪造迁移行 | 同上 ABORT ✅ |
| 3 provenance_ref 操纵 | 无审计改写 provenance_ref | 11.4 触发器 ABORT ✅ |

**最小安全修复**（migration 11 `v01_governance_hardening`，4 触发器，ADDITIVE）：
11.1 状态对白名单 / 11.1b type 边界（inferred→asserted、hypothesized→validated|asserted）/ 
11.2 provenance 存在性 / 11.3 provenance_ref 一致性 / 11.4 无审计 provenance_ref 改写守卫。
**未删除任何触发器，未把安全性退回纯 Python。**
