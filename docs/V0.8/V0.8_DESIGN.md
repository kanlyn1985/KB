# V0.8 Design — Hypothesis Lifecycle & Knowledge Evolution

- Document ID: AKB-DD-V08-001 · Version: V1.0 · Status: DESIGN BASELINE（待评审）
- 基线：V0.7 FROZEN（3df1811）· V0.7 design 14a6ea0（frozen，零修改）·
  V0.6 FROZEN（b317c6e）· V0.5 FROZEN（e7a286e）
- 性质：DESIGN ONLY——零代码/零 migration/零测试修改/零 frozen 触碰

## 1. 能力缺口分析（V0.5/V0.6/V0.7 已具备 → V0.8 缺口）

已具备（实测锚定）：
- **V0.5** validated graph（六类 Node/六类 Edge 投影、只读确定性查询、五级
  provenance、invalidation/flagged 语义）；
- **V0.6** graph-aware reasoning orchestration（Context Builder + 单一引擎编排 +
  provenance 闭环 + deterministic contract）；
- **V0.7** domain/rule/policy/guard runtime（领域词汇声明、规则版本化分发、
  policy 即数据、跨域 fail-closed 隔离）。

**V0.8 缺口（能力边界）**：
1. **知识演化缺闭环**——推理产出 candidate 后只能人工晋升/否决；无系统性的
   "猜想→验证→证据→定论"生命周期；Hypothesis 两次被 defer（V0.6 D、V0.7 D）
   ——这是唯一高价值未实现候选；
2. **验证任务缺管理**——hypothesis 的验证需要可追踪的验证动作（谁/何时/依据什么
   evidence 裁决），当前无此对象；
3. **知识演化缺审计**——一个断言从 candidate 到 validated 的演化路径散落
   （akb_assertions.updated_at + transition 审计），无"演化视图"；
4. **实验性知识无隔离**——hypothesis 若进入 akb_assertions 会与 validated
   事实同表竞争（污染 V0.5 投影面）——需要独立通道。

## 3. 核心模型（零 frozen 状态机修改——独立通道）

### 3.1 Hypothesis（hypothesis ≠ inference ≠ assertion——V0.6 不变量延续）

```text
hypothesis_id（缩写 hyp_id，与 ARCHITECTURE contract 术语一致）
                 = "hyp_" + SHA256(canonical_json({statement, origin, context_ref})).hexdigest()[:16]
statement        = 猜想内容（subject_ref/predicate_ref/object 形态或自由文本）
origin           = "reasoning"（源自 V0.6 candidate 集合）| "human"（专家提出）
context_ref      = 产生它的 ReasoningContext（origin=reasoning 时必填——可回溯）
status           = "open" | "supported" | "refuted" | "withdrawn"（独立生命周期，
                   零进入 akb_assertions.status CHECK 域）
created_by       ——human/actor；created_at
```

**关键红线**：Hypothesis 存储走**独立通道**（实现期：新表 or JSON 审计事实——
migration 决策见 §6），**零进入 akb_assertions**——V0.5 投影面零污染
（hypothesized 不进入图的不变量在 V0.5/V0.6/V0.7 已三次实测锚定，V0.8 延续）。

### 3.2 VerificationTask（验证动作管理）

```text
task_id          = "vt_" + SHA256(...)[:16]
hypothesis_id    → 所属猜想
assigned_to      ——human 验证者（human-only——governance 边界）
evidence_refs    ——验证依据（必须引用真实 akb_evidence）
verdict          = "support" | "refute" | "inconclusive"（Human feedback loop 机制）
status           = "pending" | "completed"
```

### 3.3 EvolutionView（知识演化审计视图——只读）

```text
trace(assertion_id) -> 演化路径：
  candidate → (验证/hypothesis 联动) → validated/rejected/deprecated
  每步 = transition 审计（akb_provenance）+ 关联 hypothesis/verdict 引用
```

### 3.4 Human Feedback Loop（并入 A 的裁决机制）

```text
Verdict 提交（human-only）→ hypothesis.status 变更（open→supported/refuted）
  → supported + 复验 → 可发起 PromotionCandidate（提案，非事实）
  → Governance（human）按 V0.4 既有通道转正为 assertion（candidate 态入
    akb_assertions，走正常治理）——inferred→asserted 禁令不变；
    hypothesis 的"转正"必须以新 assertion（candidate）落地，零直通。
```

## 4. 数据所有权 / V0.7 runtime 边界

| Owner | 拥有 | 禁止 |
|---|---|---|
| HypothesisRuntime（V0.8 新增） | hypothesis/verdict/task 生命周期 | 直接写 akb_assertions；修改 frozen 状态机 |
| Governance | promotion 批准（human-only） | 自动化 |
| V0.7 runtime | 领域/规则/策略/隔离 | 被 V0.8 修改（hypothesis 产生可**引用** policy_ref/pack_ref——只读） |
| V0.6 编排 | candidate 产生 | hypothesis 直通 assertion |
| V0.5 graph | 结构事实 | hypothesis 入图（延续三次实测不变量） |

## 5. 确定性 / provenance / governance 三原则延续

- **deterministic first**：hypothesis_id/task_id 全 canonical JSON 派生；verdict
  裁决为 human 动作（审计确定，结果不确定——与 V0.4 human transition 同语义）；
- **provenance first**：新活动命名空间 graph:hypothesis-*（create/verdict/
  promote-request）全进 akb_provenance——零第二套系统；
- **governance boundary**：hypothesis→assertion 只能经 Governance human 批准 +
  V0.4 既有 candidate 通道；inferred→asserted 禁令零触碰。

## 6. Migration Decision

**实现期决策点（二选一，设计倾向 a）**：
a. **NO MIGRATION**——hypothesis/verdict 全部走 akb_provenance 审计事实
   （graph:hypothesis-create/verdict 活动 + metadata 快照）；查询面从
   provenance 重建（EvolutionView 只读推导）。优点：零 schema 变更、零 rollback
   负担；缺点：查询面 JOIN 较重；
b. 新表 akb_hypotheses/akb_verification_tasks（migration 16）——仅在实现期证明
   a 的查询面不可行时启用；需实现期任务书明确批准并给出 rollback。

## 7. 范围划定

- **V0.8 进入**：Hypothesis lifecycle（create/verdict/promote-request）、
  VerificationTask、Human Feedback Loop（verdict 机制）、EvolutionView（只读）；
- **V0.9+**：multi-step causal reasoning（需因果 ontology 先冻结）、runtime
  optimization（registry 持久化/批量注入/pagination）、hypothesis 自动实验设计；
- **永久禁止**：LLM as source of truth/validation authority、vector database、
  embedding、distributed system、autonomous agent、hypothesis 直通 assertion、
  learning 自动改规则/权重。
