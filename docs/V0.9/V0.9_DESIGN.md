# V0.9 Design — Causal Knowledge Layer & Knowledge Health Governance

- Document ID: AKB-DD-V09-001 · Version: V1.0 · Status: DESIGN BASELINE（待评审）
- 基线：V0.8 FROZEN（0e49c3d）· V0.8 design 9ae6b92（frozen）· V0.7 FROZEN（3df1811）·
  V0.6 FROZEN（b317c6e）· V0.5 FROZEN（e7a286e）
- 性质：DESIGN ONLY——零代码/零 migration 实施/零测试修改/零 frozen 触碰
- **本设计的核心判断**：AKB 是否从"知识生命周期管理系统"进入"知识结构理解系统"
  ——即因果层是否值得成为下一层抽象，而不是继续增加 runtime。

## 1. 能力缺口分析（V0.5..V0.8 已具备 → V0.9 缺口）

已具备（frozen 实测锚定）：
- V0.5 validated graph（kg_* 只读投影/查询/provenance/状态语义）；
- V0.6 reasoning orchestration（context/单一引擎/闭环/contract）；
- V0.7 domain/rule/policy/guard runtime（多域隔离/版本化策略/跨域 fail-closed）；
- V0.8 hypothesis lifecycle + verification loop + evolution view（实验性知识
  独立通道 + human 裁决 + 只读审计视图）。

**V0.9 缺口（真实能力边界）**：
1. **知识只有"是什么"，没有"为什么"**——当前边类型（supports/contradicts/
   derived_from/validates/relates_to/extracted_from）全部是认识论关系
   （epistemic），无因果语义（cause/effect/condition/mechanism）。冲突检测
   （V0.3 RR-04）只能发现"值不一致"，无法理解"机制冲突"；
2. **知识健康度不可见**——V0.8 EvolutionView 是单对象视图；无跨对象的知识
   老化（temporal decay）、冲突密度、孤立断言等健康信号；
3. **验证深度有上限**——hypothesis 验证只校验 evidence 存在性，无"证据强度
   语义"（多源独立性/时效性）；
4. **查询面性能**（P1 延续）——provenance-only 全表扫描。

**关键判断**：缺口 1 是**抽象层缺口**（需要新本体层），缺口 2 是**治理视图
缺口**（需要新聚合），缺口 3/4 是**工程优化**（P1/P2 延续项）。三者性质不同，
不应混入同一阶段。

## 3. Causal Knowledge Model（Candidate A 核心裁定）

### 3.1 因果边界五律（Causal relation ≠ Assertion 红线细化）

1. **CausalRelation ≠ Assertion**——因果断言是"关于因果的断言"（assertion about
   causality），其**内容**以 assertion 形态进入 V0.4 通道（谓词为
   `causes|caused_by|enables|prevents`，走既有 create_candidate/governance）；
   其**结构**（因→果→条件→机制图）以 CausalEdge 形态进入**独立因果投影**
   ——两层永不混淆；
2. **Causal hypothesis ≠ Fact**——因果猜想走 V0.8 Hypothesis 生命周期
   （origin=reasoning，statement 为因果形态），验证/裁决机制零修改；
3. **kg_* read-only 不变**——因果层不写 kg_nodes/kg_edges；因果投影是
   assertion（因果谓词）之上的**派生视图**（同 V0.5 投影哲学：facts→projection）；
4. **Causal projection 可重建**——因果图无独立事实地位，任意时点可从
   assertions 全量重投影（fingerprint 锚，V0.5 先例）；
5. **counterfactual = hypothesis 专属**——反事实陈述（"若无 X 则无 Y"）语义
   不可直接断言，只允许以 hypothesis 形态存在（origin=human 或 reasoning）。

### 3.2 CausalProjection 模型（只读派生）

```text
CausalProjection（从 akb_assertions 中因果谓词断言派生）
  causal_node   = assertion 的 subject/object 实体（复用 V0.5 identity，零新 id 算法）
  causal_edge   = {cause_ref, effect_ref, condition_refs[], mechanism_desc,
                   assertion_id, status(继承断言治理态), provenance_ref}
  fingerprint   = SHA256(canonical_json(edges))——全量重投影锚（V0.5 先例）
隔离：CausalEdge ≠ kg_edges（不同名字空间/不同存储通道——设计 §6 migration 决策）；
consumes：V0.5 Q-01..06 只读 + hypothesis 通道 + governance。
```

## 4. Knowledge Health Governance（Candidate C 裁定）

```text
KnowledgeHealth（只读聚合，继承 EvolutionView 模式）
  causal_conflict_density   —— 同 effect 多 cause 且互斥条件的密度（依赖因果投影）
  temporal_decay_signal     —— 断言年龄 × evidence 时效（V0.3 temporal 只读）
  orphan_assertion_count    —— 零 evidence/零关联的断言
  hypothesis_staleness      —— open 长期无 verdict（V0.8 P2 延续）
MaintenanceTask（提案对象——system 只产提案）
  自动生成的维护建议（重验证/退役审查/冲突仲裁请求）
  **硬红线**：system cannot modify knowledge automatically——task 只能是提案，
  执行必须 human（governance），走 V0.8 VerificationTask 通道（task_type 扩展，
  生命周期零修改）
ConflictRecord（v2——机制级冲突）
  V0.3 conflict 只对"值不一致"；V0.9 扩展"因果机制冲突"（同 effect 互斥机制）
  ——检测在 CausalProjection 上进行，产出仍是 conflict 标注（flag 语义不变，
  裁决 human）
```

## 5. 三原则影响分析

- **Determinism**：因果投影 deterministic（assertions+时点 → 同 fingerprint）；
  health/maintenance 提案 deterministic（同库状态 → 同提案集）；
  human 裁决语义不变；
- **Provenance**：新活动命名空间 graph:causal-project（投影审计）/
  graph:health-scan（健康扫描）/ graph:maintenance-proposal（提案）——复用
  akb_provenance 零第二套系统；CausalEdge.provenance_ref 指向源断言审计；
- **Governance**：因果断言晋升走既有通道零新路径；MaintenanceTask 只提案；
  ConflictRecord v2 裁决 human；**Human Promotion Boundary 不可绕过**
  （Hypothesis→Assertion 禁令、Verdict→Fact 禁令、Reasoning→Knowledge Mutation
  禁令、System→Governance 禁令四红线全部延续并新增第五条：**CausalProjection
  →kg_* 直写禁令**）。

## 6. Migration Decision

**V0.9 需要一个 migration（与 V0.5..V0.8 全部 NO-MIGRATION 不同）——设计期明确
理由并给出边界**：

1. 因果投影与健康扫描需要**可索引的物化面**（causal edges + health signals），
   provenance-only（方案 a）在因果边基数（预计 10^3-10^4 级）下 JOIN 推导
   不可行（V0.8 P1-01 的教训已实测锚定：全表扫描是既存 P1）；
2. **migration 16（版本 16，append-only）**：
   - `akb_causal_edges`（causal_edge_id PK/cause_ref/effect_ref/
     condition_refs_json/mechanism/assertion_id FK→akb_assertions/status/
     provenance_ref/fingerprint 索引）；
   - `akb_health_signals`（signal_id PK/signal_type/subject_ref/metric_json/
     computed_at/provenance_ref）；
3. 边界：**零修改既有表**（kg_*/akb_assertions/akb_provenance 零触碰——
   append-only 新增两表）；rollback = drop 两表（零数据损失——可从 assertions
   全量重投影）；
4. 实现期若证明可 materialized-in-provenance（低基数域）仍可降级为
   NO-MIGRATION——实现期任务书保留该决策点，但设计默认 migration 16。

## 7. 范围划定

- **V0.9 进入**：CausalProjection（因果谓词投影/重投影/fingerprint）、
  KnowledgeHealth（四信号只读）、MaintenanceTask（提案对象，human 执行）、
  ConflictRecord v2（机制级冲突检测）；
- **V0.10+**：runtime optimization（D——registry 持久化/batch view/索引分页）、
  ReasoningEpisode 聚合视图（若 provenance 展示有真实需求）；
- **永久禁止**：multi-agent autonomous（E）、learning 自动改规则、LLM truth
  source、CausalProjection 直写 kg_*、system 自动执行 maintenance。
