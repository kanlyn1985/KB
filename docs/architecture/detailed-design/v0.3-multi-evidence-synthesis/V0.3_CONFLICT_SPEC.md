# V0.3 Conflict Spec

- Document ID: AKB-DD-V03-007 · Status: Design Baseline
- 铁律：冲突检测**永不静默丢弃任一方**——每个冲突保留全部双方/多方记录。

## 7 类冲突

| 类 | 触发规则 | 关键字段 |
|---|---|---|
| VALUE_CONFLICT | 同簇同谓词 object 字面值不同（数值/单位归一后） | 各方值+来源 |
| TEMPORAL_CONFLICT | valid_time 区间 contradictory / event_time 不一致且实体簇重叠 | 各方 TemporalParse |
| SOURCE_CONFLICT | 同一事实由互斥 source_type 或矛盾 document version 供给 | source_id/version |
| ONTOLOGY_CONFLICT | 同 surface 映射到不同 ontology_ref（跨证据） | 各方 ontology_ref |
| RELATION_CONFLICT | 同实体对被赋予互斥谓词（A has_parameter B vs A constrained_by B 同值） | 谓词对 |
| STATE_CONFLICT | 同实体同时间窗状态态互斥 | 状态值+valid_time |
| IDENTITY_CONFLICT | 同 normalized_form 映射到不同 entity_type 且 confidence 均 >0.7 | 类型+confidence |

## 冲突记录必需字段（任务书 §11）

source_evidence_ids[] / unit_ids[] / conflicting_fields[] / detection_method（规则号）/
confidence / provenance_ref / provider_id（若 provider 参与）/ audit 时间戳（审计字段，
不入语义）。

## 上限语义

conflicts > MAX_CONFLICTS（默认 128）→ ConflictSet.capped=True → run.status=capped →
转人工复核（**不静默降级/不丢弃/不自动裁决**——治理入口）。

## 与治理的接缝

CONFLICTING 兼容级簇可产候选（候选带 conflict_ref），治理流程依 conflict_ref 复核后
走 V0.1 状态机——V0.3 不做裁决。
