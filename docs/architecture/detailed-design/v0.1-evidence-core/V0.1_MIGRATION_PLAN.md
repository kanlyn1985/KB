# V0.1 Migration Plan

- Document ID: AKB-DD-V01-006 · Version: V1.0
- 原则：**ADDITIVE FIRST**（不删除/不改写既有列）；既有对象是编译输入，迁移产物是治理对象。

## 1. Schema 现状 → 目标

```text
Current（node-index.sqlite3）                Target（同库，+akb_ 前缀新表）
├─ documents (0 行, 旧编译表)                ├─ akb_sources        (新)
├─ evidence (29528, evd:node:*)              ├─ akb_documents      (新)
├─ facts (434)                               ├─ akb_evidence       (新)
├─ graph_edges (467, 含 origin 元数据)        ├─ akb_semantic_units (新)
├─ object_projections / retrieval_cards      ├─ akb_assertions     (新)
├─ retrieval_runs / feedback                 ├─ akb_assertion_transitions (新)
└─ search_fts / embedding_vectors            └─ akb_provenance     (新)
                                             + graph_edges.assertion_ref (ADD COLUMN)
```

**命名前缀决定**：现有 `evidence/documents` 表名已被 KB1 编译链占用（同名不同语义），
V0.1 新表统一 `akb_` 前缀——这是存储层命名隔离，**不改变 Canonical 语义**（对象名仍按 DM-003/005）。

## 2. 迁移内容与映射

| Existing | Target | Transform | Loss | Risk |
|---|---|---|---|---|
| facts (434) | akb_semantic_units + akb_assertions(candidate) | fact→SemanticUnit(evidence 链保留) + fact→candidate assertion（subject=entity_ref, predicate=fact_type 语义映射, object=value） | 无（facts 原行不动） | 中：predicate 词表映射需人工核对表 |
| graph_edges (467) | graph_edges.assertion_ref + akb_assertions(candidate) | 每边生成关系断言（subject=source_id 实体, predicate=边类型, object=target_id 实体, evidence=骨架导入 provenance）→ 回填 assertion_ref | 无 | 中：见 §3 |
| evidence (evd:node:*) | 映射记录（不搬运） | 建立旧 evd:node:* ↔ 新 akb_evidence 行的引用映射（存量证据保持原位，V0.1 只为新写入用新表？——**否**：映射策略见 §3 决定） | 无 | 低 |
| retrieval_cards / object_projections | 不迁移 | 属检索投影（ADR-005），由断言体系未来重建 | 无 | — |
| source_units（无独立表，散在 evidence 编译） | akb_semantic_units | 编译期 SemanticUnit 重放 | 无 | 低 |

### §3 关键决定：存量 evidence 的处理

现有 29528 条 `evd:node:*` 是节点卡聚合产物（document=doc:node:*，无独立 Document/Source 行）。
**V0.1 采用"影子映射"而非搬运**：
1. 迁移脚本为每个 distinct `doc:node:<node>` 建一行 akb_documents（content_hash=节点卡内容哈希，
   source=src_kb1_corpus），为每个节点建一行 akb_sources（如无）；
2. 存量 evidence 行**原位保留**，assertions.evidence_refs 允许引用旧格式 id
   （`evd:node:*` 字符串）——Validator 的 evidence 解析器支持双格式（新 evd_ 前缀查 akb_evidence；
   旧 evd:node:* 查原表）；新写入一律走 akb_evidence；
3. 完整搬运到 akb_evidence 属 V0.2（数据量 29528×重哈希，非 V0.1 必要路径）。
   此决定保证 Golden 的 evd:node:* 引用在 V0.1 迁移后继续可解析（回归安全）。

## 3. graph_edges 回填策略（AG-001）

1. 为 467 条边各生成一条 candidate 关系断言（batch=1 provenance 行，actor=system:migrator）；
2. edges 按 (source_id,target_id,predicate) 内容寻址去重（重复边共享断言）；
3. UPDATE graph_edges SET assertion_ref=? WHERE rowid=?（逐行，每 100 行一事务）；
4. 校验：assertion_ref IS NOT NULL 比例 = 100% 才算通过（V0.1-GRAPH-001）。

## 4. ID 生成

- 断言：`ast_m{批次号:03d}_{序号:04d}`（迁移批次） / `ast_{ulid}`（运行时）；
- 铸造规则统一入库（schema registry 备注）；禁止 provider id 作为 id 组成部分（ADR-009）。

## 5. Duplicate handling

- 断言去重键：(subject_ref, predicate_ref, object_value|object_entity_ref, assertion_type)；
- 迁移时同键多行 → 保留首条，其余记 provenance(activity=dedupe, inputs=被并 id)；
- 运行时 create_candidate 不去重（冲突由 list_conflicts/G016 流程处理——治理问题非存储问题）。

## 6. Rollback / Partial failure / Backup

| 场景 | 处置 |
|---|---|
| 迁移前 | 强制备份：`BackupManager.snapshot(pre_v01_migration)`（现有 storage 设施）+ 记录 backup_id 于迁移日志 |
| 批内失败 | 单事务回滚（100 行/批）；断点表记录已完成批次 |
| 重跑 | 幂等：已完成批次 0 变更跳过（V0.1-MIG-002） |
| 整体回滚 | DROP 新表（它们只被迁移写入）+ graph_edges 删列（SQLite 3.35+ ALTER DROP COLUMN 或重建表脚本）+ 恢复备份兜底 |
| 半成品检测 | 启动巡检：新表行数 vs 断点表计数一致性；assertion_ref 指向不存在的 assertion_id 计数=0 |

## 7. Validation after migration（门禁）

```text
[ ] akb_assertions 行数 = 预期映射数（facts+edges 去重后）
[ ] 全部迁移断言 status=candidate 且 provenance 链闭合
[ ] graph_edges.assertion_ref 回填率 = 100%（467/467）
[ ] INV-001 数据层 CHECK：无 evidence_refs 的 validated+ 行数 = 0
[ ] Golden validator PASS（golden 引用 evd:node:* 经影子映射可解析）
[ ] run_skeleton_health / run_retrieval_health 零回归（既有面不受迁移影响）
[ ] run_production_health PASS（投影面一致性）
```

## 8. 执行序列

```text
备份 → M1 建表（7 akb_ 表 + 触发器）→ M2 evidence 影子映射 → M3 facts 迁移 →
M4 graph_edges 断言生成+回填 → M5 校验门禁 → 完成标记（schema_migrations 登记）
任何一步失败 → 回滚该步 → 人工决策（续跑/整体回滚）
```
