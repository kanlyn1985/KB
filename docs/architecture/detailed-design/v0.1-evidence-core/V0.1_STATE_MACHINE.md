# V0.1 State Machine — assertion_type × status 双轴

- Document ID: AKB-DD-V01-003 · Version: V1.0
- 依据：DM-005 §9.3/§9.4、ADR-003/004、INVARIANT_REGISTRY INV-001/002/005/008/009

## 1. 双轴原则（ADR-004）

`assertion_type`（知识从哪来）与 `status`（治理走到哪）是**两个独立维度**，组合必须落在本文件
§3 合法矩阵内。类型定义（DM-005 §9.3 原义）：

| assertion_type | 语义 |
|---|---|
| extracted | 从内容自动抽取的候选声明 |
| observed | 来自系统/传感器/人工的观测 |
| asserted | 经治理接受的权威断言 |
| inferred | 由规则/推理得到（必带 derivation 块） |
| hypothesized | 尚待验证的假设 |

状态定义（DM-005 §9.4 原义）：`candidate → validated → asserted → disputed/deprecated`；
`candidate → rejected`；任何迁移记录 actor/timestamp/reason/policy_version/previous_status。

## 2. Evidence Gate（INV-001 / ADR-003）

```text
                ┌────────────────────────────────────────────┐
                │                                            │
 candidate ──validate──> 有有效 evidence_refs？               │
                │        │否                      │是        │
                │        v                        v          │
                │   REJECT 或 remain candidate   validated ──promote──> asserted
                │                                            │            │
                │                                            │      dispute/dispute-resolve
                │                                            │            v
                └────────────────────────────────────────────┘      disputed
```

Evidence requirement per status（数据层 CHECK + Validator 双强制）：

| status | evidence_refs 要求 | 说明 |
|---|---|---|
| candidate | 可为空 | 前治理态（ADR-003 epistemic boundary） |
| rejected | 可为空 | 拒绝亦无证据要求（但 reason 必填） |
| **validated** | **≥1 必填** | INV-001 |
| **asserted** | **≥1 必填** | INV-001 |
| **disputed** | **≥1 必填** | 争议双方主张均可溯源 |
| deprecated | 保持进入时的证据（继承） | 被新版本取代 |

observed 的弱信号规则：evidence 允许 observation-scope 类型（system_record/filename 规约），
confidence 上限 0.75（Golden G008 先例），不适用 text 类证据的 ≥0.9 期待。

## 3. 合法状态矩阵（type × status）

图例：✅=允许进入（创建或迁移目标）　⛔=禁止组合　－=可达但非常态

| type \ status | candidate | validated | asserted | disputed | rejected | deprecated |
|---|---|---|---|---|---|---|
| extracted | ✅（创建） | ✅（validate） | ✅（promote） | ✅ | ✅ | ✅ |
| observed | ✅（创建） | ✅（validate，弱信号规则） | ✅（promote） | ✅ | ✅ | ✅ |
| asserted | ⛔（创建即 asserted=绕过治理，INV-001） | ⛔（同左） | ⛔（直接创建禁止；只能经迁移达到） | －（后续可 disputed） | ⛔ | ✅（被取代） |
| inferred | ✅（reasoner 产出，唯一允许创建态） | ✅（推导链证据充分时 validate，仍带 derivation） | ⛔（**inferred 禁止 promoted 到 asserted**——必须先转为 extracted/human re-entry 走独立治理） | ✅ | ✅ | ✅ |
| hypothesized | ✅（创建，**只能保持 candidate**） | ⛔（**禁止**——须先重新分类为 extracted/observed 再进 validation pipeline） | ⛔（**禁止**） | ✅ | ✅ | ✅ |

**关键禁组合（非法迁移表，Validator 强制，V0.1-AST-005）**：

1. 任何直接创建 `status=asserted` 的行（必须经 candidate→validated→asserted 治理链）；
2. `inferred → asserted` 直接晋升（ADR-004：禁止自动晋升；须人工 re-entry）；
3. `validated → candidate` 回退（历史不可逆——INV-005；只能 deprecated）；
4. 无对应 transitions 审计行的任何 status 变更（触发器阻断）；
5. `rejected → 任何`（终态）；
6. evidence_refs 为空时进入 validated/asserted/disputed（INV-001）。

## 4. 迁移权限矩阵（谁可以触发）

| 迁移 | 允许的 actor_kind | 说明 |
|---|---|---|
| create(candidate) | human / system:compiler / system:reasoner / llm:gateway | 全部入口统一（INV-007：LLM 无特权通道，产出即 candidate） |
| candidate→validated | **system:validator**（自动，当 evidence 校验通过）或 human | validator 是唯一自动验证者 |
| validated→asserted | **human**（治理跃迁，须经 review） | 系统禁止自动 promote |
| validated→disputed | human / system:conflict-detector | G016 冲突场景 |
| asserted→disputed | human / system:conflict-detector | 新证据挑战 |
| disputed→asserted | human（裁决恢复） | 记录裁决 reason |
| disputed→deprecated | human | 争议后废弃 |
| any→deprecated | human | 被新版本取代 |
| candidate→rejected | system:validator（校验失败自动）或 human | reason 必填 |

## 5. 幂等与重复执行

- 同一断言同一目标状态的重复迁移请求：若当前 status 已等于目标 → **幂等成功（no-op，返回现有状态）**；
- 若存在中间迁移（validated→asserted 之间插了 disputed）→ 拒绝并返回迁移历史；
- transitions 表 append-only 保证审计不可篡改（触发器）；迁移本身在单事务内完成
  （BEGIN: INSERT transition + UPDATE assertions.status → COMMIT），部分失败自动回滚。

## 6. 失效与投影联动（ADR-002）

断言 status 变为 deprecated/rejected 时：
- graph 投影策略 = **标记删除**（assertion_ref 指向的边打 tombstone 标记，物理删除留给 rebuild）；
- 向量/词法投影不受影响（它们按 canonical id 引用，rebuild 时自然排除）；
- **禁止**投影组件反向修改 assertions（INV-006；V0.1-GRAPH-002 验证）。
## 7. Migration Backfill vs Runtime Projection（两条独立路径，禁止混用）

```text
PATH A — Migration Backfill（legacy compatibility linkage，仅迁移脚本）
  existing graph_edges (legacy)
      → 为每条边生成 candidate assertion（actor=system:migrator）
      → graph_edges.assertion_ref 回填
  性质：兼容性链接，不是新的 Canonical Projection。
  允许 candidate 断言被回填关联——这是历史事实的登记，不是投影授权。

PATH B — Runtime Projection（唯一正常投影通道）
  只有 status ∈ {validated, asserted} 的断言
      → 经 project_edge() 进入 graph_edges
  candidate / hypothesized / rejected / deprecated → 禁止（E-ILLEGAL-TRANSITION 类拒绝）。
```

- 两条路径共用同一 assertion_ref 列，但入口、前置条件、审计活动（activity=migrate vs project）完全不同；
- 禁止将 PATH A 解释为"candidate 可以进入正常投影"；
- 验证拆分：V0.1-GRAPH-001A（Runtime） / V0.1-GRAPH-001B（Migration Backfill），见 Verification Spec。

## 8. Append-only 与 Transition 原子性（正式语义）

- akb_assertions 为 **Business-level append-only**（DB Design §5/§9.2）：
  核心列不可变；status/updated_at/provenance_ref 仅可由受控 transition 改变；
- **transition 原子序列（单事务，任一步失败 ROLLBACK ALL）**：

```text
transition request
    +-- validate permission（状态机 §4 权限矩阵）
    +-- validate state transition（§3 合法矩阵）
    +-- validate evidence（INV-001：目标状态证据要求）
    +-- INSERT akb_assertion_transitions
    +-- UPDATE akb_assertions（status/updated_at/provenance_ref 受控列）
    +-- INSERT akb_provenance
    +-- COMMIT
```

- 直接 SQL UPDATE status（无同事务 transitions 行）→ 触发器 FAIL（DB Design §9.2b）；
- 验证：V0.1-AST-005/006。
