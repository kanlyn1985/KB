# V0.2 Ontology Mapping Spec

- Document ID: AKB-DD-V02-007 · Status: Ready for Implementation

三段式（任务书 §11）：

```text
surface concept（normalized_form + entity_type）
      ↓  OntologyMapper（DomainPack 词表匹配）
candidate ontology mapping（mapping_status=candidate，confidence）
      ↓  治理流程（人工复核 / 后续治理接口——V0.2 不实现）
validated ontology reference（authoritative mapping）
```

## 规则

O-01 精确匹配：normalized_form ∈ DomainPack 词表 → mapping_status=candidate, confidence=1.0；
O-02 规范化匹配：经 N-04..N-06 归一后命中 → candidate, confidence=0.9；
O-03 别名匹配：DomainPack.aliases 命中 → candidate, confidence=0.8（别名表版本化）；
O-04 无命中 → mapping_status=quarantined（E-ONTOLOGY-MAPPING-FAILED 记 run.warnings，
      该候选不参与 assertion 构建——**quarantine 而非静默丢弃**）；
O-05 阈值模糊匹配：仅当 config 提供 threshold 且固定（默认禁用——避免 provider 式不确定性）；
O-06 DomainPack 不可变：compiler 禁止修改 ontology（词表演进 = DomainPack 版本化发布）。

## 边界

- Ontology mapping 默认 candidate：accompanying assertions 继承 ontology_scope 的
  candidate 语义；authoritative 映射（mapping 治理）是后续治理产物，V0.2 只提供 quarantine 队列。
- Semantica ER 产出（未来）＝一个 SemanticCompilerProvider 的输入源，其输出同样走
  schema validation → candidate mapping（ADR-006 adapter 边界不变）。
