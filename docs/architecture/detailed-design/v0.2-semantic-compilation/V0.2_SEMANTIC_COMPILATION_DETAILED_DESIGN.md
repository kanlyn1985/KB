# V0.2 Semantic Compilation Core — Detailed Design

- Document ID: AKB-DD-V02-001 · Version: V1.0 · Status: Ready for Implementation（待架构评审确认）
- Accepted Baseline: V0.1 Evidence Core ACCEPTED（base fc65370）
- 约束：V0.1 Governance Boundary 优先于实现便利（任务书 §31 铁律）

## 1. 代码考察结论（§3 六问）

| 问 | 结论 |
|---|---|
| 1. 已有 Evidence→SemanticUnit 能力？ | `core/source_units.py`：分段（`_semantic_segments`）、分类（definition/requirement/test_method/test_result/warning）、标题提取——面向 KB1 检索编译，**不产出治理链 SemanticUnit** |
| 2. 事实抽取逻辑？ | `core/facts.py: extract_facts`——规则式（domain subject 匹配 + 数值约束正则），输出 `Fact`（KB1 编译产物，非 Canonical） |
| 3. 可复用资产 | ①分段/分类启发式（移植为 Preprocessor/Normalizer 的 deterministic 组件）；②`domains/schema.py` 的 DomainPack/ObjectTypeSpec/RelationTypeSpec（ontology hint 来源）；③evidence_core 全套（EvidenceStore/models/state_machine/AssertionStore.create_candidate） |
| 4. legacy/adapter 面 | `core/compiler.py`（KB1 检索编译链）、`core/facts.py`、`graph/extraction.py`（DeterministicRelationExtractor）→ 一律经 compatibility adapter 进 V0.2，禁止直连 |
| 5. 新边界 | `agent_kb/evidence_core/compilation/`（V0.2 归 evidence_core 域内子包——共享连接/迁移/治理设施，**不建第二套 storage**） |
| 6. 第二套管线风险 | 现有 `pipeline/production_context.compile_text_document` 是 KB1 **检索编译**（facts/cards/graph），与 Canonical assertion 链并行存在。V0.2 边界裁决：**不重写 KB1 编译器**；Canonical 编译只吃 `akb_evidence`（经 EvidenceStore），KB1 编译产物继续走影子映射（V0.1 MIGRATION_PLAN §3）。两链路通过各自的 provenance activity（compile vs project）区分，合并留给 V0.3+ |

## 2. 目标数据流（冻结）

```text
Source → Document → Evidence（V0.1，immutable）
    ↓
Preprocessor → Normalizer → Semantic Extractor → Entity/Relation Candidate Resolver
    → Temporal Parser → Ontology Mapper → Candidate Assertion Builder
    ↓
KnowledgeAssertion(status=candidate)（V0.1 治理链接管）
    ↓
Validation → Projection（V0.1）
```

## 3. 不可破坏的 V0.1 边界（设计红线）

1. Evidence.content immutable（append-only 触发器不变）；
2. Compiler 只产出 `status=candidate`，不得输出 validated/asserted；
3. inferred 必带 derivation（rule_ref/parent_assertions/reasoner_id）——INV-002；
4. LLM/Provider 只能作为 `SemanticCompilerProvider` 实现，输出经 schema validation
   → normalization → candidate creation，**永不直达 authoritative 层**；
5. Ontology mapping 默认 candidate，治理流程才能 authoritative；
6. Agent Runtime 不新增任何写路径（V0.1 静态审计测试保持通过）；
7. Semantica（ADR-006）仍是 implementation candidate，经 canonical adapter，不是 Canonical Model。

## 4. 数据模型变化（论证后新增，不做实现）

| 变更 | 类型 | 论证 |
|---|---|---|
| `akb_semantic_units` +4 列：provenance_ref / compiler_run_ref / configuration_hash / content_fingerprint | ADD COLUMN | 任务书 §7 要求 provenance_ref/compiler_run_id 进 SemanticUnit；§16 要求 fingerprint 幂等——四列均无法从既有列推导，且都是治理/审计语义（不是实现便利） |
| `akb_compilation_runs`（新表） | CREATE | 任务书 §14 建议 CompilationRun；论证：provenance 表 activity 粒度是"单次治理动作"，无法回答"哪次 compilation 用了哪个 compiler_version/configuration/ontology_version/provider"——需要 run 级聚合实体。7 列设计见 DB 文档 |
| 既有 V0.1 表 | **零改动** | assertions/transitions/provenance/evidence/sources/documents 语义与结构不动 |
| Canonical Model 对象 | SemanticUnit/EntityCandidate/RelationCandidate/TemporalParse/OntologyMapping/CompilationRun 六个 dataclass（evidence_core.models 扩展） | DM-004 SemanticUnit 的具体化 + 4 个编译期子结构 |

## 5. 接口变化

新接口（全部在 `evidence_core.compilation`，详见 V0.2_INTERFACE_BEHAVIOR.md）：
`SemanticNormalizer / SemanticExtractor(Protocol) / EntityCandidateResolver /
RelationCandidateResolver / TemporalParser / OntologyMapper / CandidateAssertionBuilder /
SemanticCompiler(编排) / SemanticCompilerProvider(Protocol，provider 边界)`
错误码族：E-COMPILER-* / E-NORMALIZATION-FAILED / E-SEMANTIC-EXTRACTION-FAILED /
E-ONTOLOGY-MAPPING-FAILED / E-CANDIDATE-BUILD-FAILED / E-COMPILATION-{NONDETERMINISTIC,DUPLICATE,PROVENANCE-MISSING}。
