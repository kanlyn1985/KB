# V0.2 Compilation Pipeline（8 层规格）

- Document ID: AKB-DD-V02-003 · Status: Ready for Implementation
- 每层五要素：input / output / invariants / failure behavior / provenance / determinism

## L1 Preprocessor
- input: `EvidenceRecord`（akb_evidence 行，immutable）
- output: `list[TextSegment]{segment_id, span_start, span_end, text, block_type}`（复用 source_units 分段启发）
- invariants: 不修改 Evidence；span 指向原文坐标；segment 并集覆盖输入（允许空白间隙）；顺序稳定
- failure: 空 content → E-COMPILER-INVALID-EVIDENCE；单段异常 → 跳段 + warning
- provenance: run 级（activity=compile）
- determinism: strict（纯函数，输入相同输出逐字节相同）

## L2 Normalizer（SemanticNormalizer）
- input: `TextSegment`
- output: `NormalizedSegment{normalized_text, normalizer_version, rules_applied[]}`
- invariants: 原文不动（normalized 结果只存 SemanticUnit）；规则集见 NORMALIZATION_SPEC（N-01..N-08 顺序固定）；规则可追溯（rules_applied 逐条记录）
- failure: E-NORMALIZATION-FAILED（segment 级跳过）
- provenance: normalizer_version 进 SemanticUnit.extraction_version 组成部分
- determinism: strict

## L3 Semantic Extractor
- input: `NormalizedSegment`
- output: `RawExtraction{entities_raw[], relations_raw[], temporal_expressions[]}`
- invariants: 输出 schema 校验通过（provider 输出不合格 → E-SEMANTIC-EXTRACTION-FAILED）；confidence∈[0,1]
- failure: provider 异常 → run 级 failed（不产生半成品 assertion）
- provenance: extractor_id + extractor_version（deterministic 内置 or provider 标识）
- determinism: 内置规则 = strict；provider = stochastic-but-traceable（seed/prompt/version/hash 记录，见 DETERMINISM_SPEC）

## L4 Entity Candidate Resolver
- input: `RawExtraction`
- output: `list[EntityCandidate]{candidate_id, surface_form, normalized_form, entity_type, confidence, source_span, ontology_hint}`
- invariants: **Candidate ≠ authoritative Entity**（不写任何 canonical entity 表）；normalized_form 经 N-05/N-06；排序按 (span_start, normalized_form) 稳定序
- failure: 候选级丢弃 + warning
- provenance: 随 SemanticUnit
- determinism: strict（排序规则固定）

## L5 Relation Candidate Resolver
- input: `RawExtraction` + L4 产物
- output: `list[RelationCandidate]{relation_candidate_id, subject_candidate_id, predicate_candidate, object_candidate_id, confidence, source_span, ontology_hint}`
- invariants: subject/object 必须引用本 run 的 EntityCandidate（无孤儿引用）；谓词受 ontology hint 约束（unknown → candidate 保留 + mapping quarantine）；稳定排序
- failure: 候选级丢弃 + warning
- determinism: strict

## L6 Temporal Parser
- input: `RawExtraction.temporal_expressions`
- output: `TemporalParse | None`（五类时间字段，TEMPORAL_SPEC）
- invariants: 五类时间不合并；无法解析的表达保留 raw + parse_status=unresolved
- failure: 解析失败 → parse_status=failed（不阻断 assertion，temporal_scope 置空）
- determinism: strict（规则式；相对日期基于 evidence.observed_at/document.effective_at 锚定，不用当前时钟——否则破坏确定性）

## L7 Ontology Mapper
- input: candidates + DomainPack
- output: `list[OntologyMapping]{concept_surface, ontology_ref, mapping_status(candidate|quarantined), confidence}`
- invariants: **默认 candidate**；unknown ref → quarantined（该候选不参与 assertion 构建）；不修改 DomainPack
- failure: E-ONTOLOGY-MAPPING-FAILED → quarantine 路径
- determinism: strict（基于 DomainPack 词表精确/规范化匹配，阈值匹配需 config 固定阈值）

## L8 Candidate Assertion Builder
- input: `SemanticUnit`（组装完成）
- output: `KnowledgeAssertion(status=candidate)`——经 AssertionStore.create_candidate
- invariants: assertion_type∈{extracted,observed,inferred,hypothesized}；inferred 必带 derivation（rule_ref/parent_assertions/reasoner_id）否则 E-CANDIDATE-BUILD-FAILED；evidence_refs=[evidence_id]；provenance_ref=run 的 provenance 行
- failure: E-CANDIDATE-BUILD-FAILED（unit 保留，assertion 不产出）
- provenance: create_candidate 内部 provenance(activity=create) + run.provenance_ref 双链
- determinism: strict（同 unit → 同 assertion 语义内容；assertion_id 每次铸造新——幂等由 fingerprint 层保证，见 DETERMINISM_SPEC §idempotency）
