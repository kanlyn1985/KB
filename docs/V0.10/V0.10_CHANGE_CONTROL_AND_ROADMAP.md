## 3. P0 / P1 / P2 风险分级

### P0（触发即 STOP）
- migration 16 修改既有表（非 append-only）；
- persist/query 任何路径写 kg_*/akb_assertions/akb_provenance schema；
- 三 runtime identity 算法被变更（API 零破坏承诺破坏）；
- counterfactual 推理运行时被提前实现（边界契约违约）。

### P1（实现期必须解决）
- persist 幂等与并发写（SQLite 单写者模型下的锁语义——同一 connection 串行
  即可，跨进程场景需显式串行化说明）；
- total_estimate 的精确性（COUNT 查询成本 vs 近似值——设计默认精确 COUNT，
  大基数下可实现期降级为近似+标注）；
- registry 重放的多版本 registry 冲突（同 key 不同版本——load_order 决定，
  V0.7 语义延续）。

### P2（accepted 候选）
- 页游标（cursor-based pagination）替代 OFFSET（深分页性能）；
- akb_causal_edges 物化视图（effect→causes 反向索引）；
- health 信号降采样（历史趋势长窗口）。

## 4. Out of Scope（V0.11+ / 永久）

- V0.11+：机制语义比对 level-2/3（需 ontology 冻结）、MaintenanceTask 执行层、
  counterfactual 推理运行时、knowledge analytics、ReasoningEpisode 聚合视图；
- 永久禁止：multi-agent autonomous / learning 自动改规则 / LLM truth source /
  CausalProjection 直写 kg_* / system 自动执行 maintenance / 自动 conflict
  resolution / hypothesis→assertion 直通。
