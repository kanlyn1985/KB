# V0.10 Architecture & Contract

- Document ID: AKB-DD-V10-002 · 合并 ARCHITECTURE + CONTRACT（内容不减）

## 1. 架构图（持久化增强层——零语义变更）

```text
V0.9 frozen 三 runtime（只读面冻结为接口——API 零破坏）
  CausalProjection.project() ──┐
  KnowledgeHealth.create()  ───┤→ V0.10 Persistence Adapter（新增）
  ConflictRuntime.detect()  ───┘      ↓
                              migration 16 三新表（append-only）
                              akb_causal_edges / akb_health_signals /
                              akb_conflict_records
                                      ↓
                              索引 + 分页查询 contract（canonical ORDER BY）
                                      ↓
                              Registry Snapshot（provenance-only 序列化）
                                      ↓
                              V0.11+ 边界契约（counterfactual/机制比对——仅设计）
```

单一职责：V0.10 零新语义——三 runtime 的 identity 算法/状态机/governance 边界
全部不变；变的只是**存储介质与查询效率**。

## 2. Contract：Persistence Adapter（三 runtime 共用模式）

```text
persist_projection(projection) -> persisted(bool, first_write)
    —— 同 fingerprint 幂等：零重复写入；INSERT OR IGNORE 语义
persist_health(health) -> persisted(bool, first_write)
persist_conflicts(records) -> persisted(bool, first_write)
    failure: E-V10-PERSIST-INVALID（缺 fingerprint/provenance_ref——fail-closed）
    provenance: 零新活动（持久化是介质变更非知识事件——写表不写 provenance；
      graph:registry-snapshot 仅 registry 快照用）
```

## 3. Contract：分页查询（canonical ORDER BY + LIMIT/OFFSET）

```text
query_causal_edges(*, effect_ref=None, cause_ref=None, limit=100, offset=0)
    -> (edges, total_estimate)
    ordering: ORDER BY causal_edge_id（canonical，tie-breaker=PK）
    guard: limit ≤ 500（防失控——E-V10-PAGE-INVALID）
query_health_signals(*, target_ref=None, signal_type=None, limit, offset)
query_conflict_records(*, conflict_type=None, status=None, limit, offset)
    —— 三查询面同模式；零 runtime ordering 依赖
```

## 4. Contract：Registry Snapshot（跨进程一致性——provenance-only）

```text
snapshot_registry() -> registry_ref
    —— V0.7 三 registry（domain/rule/policy）+ V0.9 causal registry 的内容摘要
       序列化为 graph:registry-snapshot 审计（canonical JSON）；新进程可从审计
       重放重建 registry 状态（与 V0.8 hypothesis 重放同模式）
    identity: registry_ref = SHA256(canonical_json(各 registry 内容摘要))
    failure: E-V10-REGISTRY-INVALID
```

## 5. Contract 汇总（input/output/identity/provenance/determinism/failure）

| Contract | input | output | identity | provenance | determinism | failure |
|---|---|---|---|---|---|---|
| persist_* | runtime 对象 | persisted flag | 对象自身 id（零新算法） | 零新活动 | 同对象同写入幂等 | PERSIST-INVALID |
| query_causal_edges | 过滤+分页 | (edges, total) | — | 读面 | canonical ORDER BY | PAGE-INVALID |
| query_health_signals | 过滤+分页 | (signals, total) | — | 读面 | 同上 | PAGE-INVALID |
| query_conflict_records | 过滤+分页 | (records, total) | — | 读面 | 同上 | PAGE-INVALID |
| registry snapshot | 各 registry | registry_ref | registry_ref | graph:registry-snapshot | 同状态同 ref | REGISTRY-INVALID |

## 6. V0.11+ 边界契约（仅设计——不实现）

- **counterfactual 入口**：只允许经 V0.8 Hypothesis（statement 为反事实形态
  "若非 X 则非 Y"）；CausalProjection 提供 counterfactual_check(eid, removal_set)
  **只读推导**（移除因果源后可达性分析——确定性图算法）——禁止产生任何
  assertion/mutation；
- **机制比对分级**：level-1 条件集合互斥（V0.9 已实现）→ level-2 条件集合
  包含/重叠 → level-3 文本语义比对（需 ontology 术语冻结——V0.11 前置条件）；
- **MaintenanceTask 执行层**：依赖 akb_health_signals 历史就绪（本阶段产物）——
  human-only 执行边界不变。
