# 标准实体落位设计（GB/T、企标等标准文件怎么进树）

> 状态：✅ 已确认（2026-08-06）
> 适用范围：国标（GB/T）、行标（QC/T）、企标（Q/MA）、国际标准（ISO/IEC）及内部规范（SOR、原材料认可数据库等）

## 1. 定位

标准文件**不是产品构成**，是"权威知识来源"——拆分为三类内容后作为各层的依据：

| 条款类型 | 落到哪 | 方式 |
|---|---|---|
| 要求类条款（§4 技术要求） | R 层（需求来源） | 变成"通用需求点"（行业级要求），项目需求条目通过 conforms_to 引用 |
| 试验类条款（§5 试验方法） | 验证过程（verify 边） | 变成"验证方法点"，测试活动通过 references 引用 |
| 术语类条款（§3 术语定义） | 所有层的概念定义 | 节点的"定义依据"（定义 references 标准术语） |

## 2. 条款树（完整性基线，全量录入）

**条款树 = 标准实体（证据类）的内部结构**，不并入产品构成树。产品树节点通过引用边指向条款节点。

```
条款节点 = {
  条款号: "4.2.1",              ← 条款号本身是层级树（part-of 4.2）
  标题: "输入电压范围",
  条文: "充电模式下输入电压为 85V 至 265V AC…",   ← 原文（或摘要）
  条款类型: 要求 / 试验 / 术语 / 检验规则,
  版本适用: "GB/T 40432-2021"
}
```

**关键决策：条款必须全量录入（不是惰性展开）**——汽车行业漏一条要求不可接受。

## 3. 三层保证（防漏的纵深）

```
① 录入层（完整性基线）：条款全量解析入库
   条款解析器（确定性规则）：标准文本 → 条款号模式识别（4.2.1/5.3/附录A）→ 条款树
   "完整性" = 条款树与标准原文一一对应（可核对）

② 覆盖层（引用落位）：需求/验证引用时建立 conforms_to / references 边
   引用后置，但每条条款都带"覆盖状态"

③ 审计层（覆盖闭环）：强制逐条确认
   每条条款的覆盖状态只能是：
   ├─ 已覆盖：被需求/验证引用（conforms_to/references ≥1）
   ├─ 不适用：本产品不适用 → 必须记录理由 + 审批人 + 审批日期
   └─ 待审计：未引用且未评估 → 进入审计清单（红灯）
   ★ 不存在"沉默条款"——未处理的条款永远可见
```

## 4. 符合性矩阵（汽车行业标准做法）

每个项目一份"标准条款符合性矩阵"（对标 SOR 响应/法规符合性矩阵/PPAP 顾客特殊要求清单）：

```
┌──────────┬──────────┬──────────┬──────────┬──────────┬────────┐
│ 条款号    │ 条文摘要  │ 适用性    │ 覆盖需求  │ 验证方法  │ 状态   │
├──────────┼──────────┼──────────┼──────────┼──────────┼────────┤
│ 4.2 充电  │ ……      │ 适用      │ MI-MD-13065│ 电气性能  │ ✅    │
│ 5.9 逆变  │ ……      │ 不适用    │ —        │ —        │ N/A   │
│          │          │ (无逆变功能)│ 理由+审批人 │          │ ✅    │
│ 附录A    │ ……      │ 待审计    │ —        │ —        │ 🔴    │
└──────────┴──────────┴──────────┴──────────┴──────────┴────────┘
```

**漏条款 = 可见的待办（红灯），不是无声消失**。

## 5. 技术实现

```
① 条款解析器：标准 PDF 文本 → 条款号正则（4.2.1/5.3/附录A）→ 条款表全量入库
② 条款表（完整性基线）：(条款号, 条文, 条款类型, 层级parent, 标准ID, 版本)
③ 条款覆盖表（每项目一份）：(条款ID, 项目ID, 状态: 已覆盖/不适用/待审计,
                               reason, approver, approved_at, 覆盖需求IDs, 验证方法)
④ 审计报告（落位时/周期性自动跑）："未覆盖条款清单" = 状态=待审计 的条款
   ——项目发布/PPAP 前，此清单必须为空（或全部转为不适用+审批）
```

## 6. 追溯与变更影响

```
正向：需求 → 条款 → 条文原文（查依据）
反向：条款 → 所有 conforms_to/references 它的需求/验证（查影响面）
标准改版：supersedes → 反查所有引用 → 受影响需求强制复审
```

## 7. 覆盖范围

- 国标（GB/T）、行标（QC/T）、企标（Q/MA）、国际标准（ISO/IEC）
- 内部规范文件（SOR、原材料认可数据库、质量协议等）按同一规则：文档/标准实体，条款树全量录入，被引用才建立引用边
