## 2. 数据流（端到端）

1. V0.9 health scan / conflict detect 产出信号（V0.10 已持久化）；
2. 运维者或治理节奏触发 `create_proposal_from_signal/conflict`（确定性转换）；
3. 提案落地为 V0.8 VerificationTask（status=created，human-only 迁移）；
4. human 按 V0.8 生命周期执行（start→complete/fail/cancel）；
5. 裁决产出（修订断言/退役标记/升级 hypothesis）走既有 frozen 通道；
6. 全程 provenance 审计（graph:maintenance-proposal-create + V0.8 既有
   task 活动面）。

## 3. Contract 字段级定义

### 3.1 MaintenanceProposalRuntime

```text
create_proposal_from_signal(signal_ref, *, actor_id) -> VerificationTask
    校验: signal_id 实存（akb_health_signals）→ else
          E-V11-PROPOSAL-SIGNAL-NOT-FOUND（fail-close 零 fabricate）
    target 解析: signal.target_ref → assertion 型直接映射；entity/hypothesis
          型走 created_from 锚（P1 定标项——确定性规则）
    identity: task_id = V0.8 verification_task_identity（复用零新算法）
              task_type = "maintenance_review"（枚举扩展）
              spec = 确定性规格（"Review health signal {signal_id}:
                     {signal_type} on {target_ref}"——模板固定，零自由文本漂移）
              evidence_requirements = (signal_ref,)
    幂等: 同 signal_ref → 同 task_id → 零重复审计
    红线: 提案不含裁决性结论（"please review" 而非 "confirmed"）

create_proposal_from_conflict(conflict_id, *, actor_id) -> VerificationTask
    校验: conflict_id 实存（akb_conflict_records）→ else
          E-V11-PROPOSAL-CONFLICT-NOT-FOUND
    identity: 同上模式（evidence_requirements=(conflict_id,)）
    红线: Conflict ≠ Resolution——提案仅请求 human review，零裁决语义

list_proposals(*, signal_ref=None, cursor=None, limit=100) -> dict
    —— V0.8 task provenance 重放 + V0.10 ScaleQueryRuntime keyset cursor
       模式复用（PAGE-INVALID guard limit≤500）
```

### 3.2 VerificationTask 扩展（V0.8 frozen 面——枚举扩展先例）

```text
VALID_TASK_TYPES += ("maintenance_review",)   # 唯一允许的 frozen 面变更
生命周期/状态机/identity 算法/审计活动——零修改
CONTRACT 面测试适配（v08 白名单断言 +1 值——同 V0.10 CONTRACT-CMP-015 先例）
```
