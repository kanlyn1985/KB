# 判断力分层：规则优先 + LLM 兜底

ContextPack 中的五种判断（证据充分性、歧义检测、知识缺口、推荐策略、意图理解）分两层实现：结构性判断走确定性规则（零延迟），语义判断走 LLM（按需调用）。

**判断分类**：

| 判断 | 类型 | 执行方式 |
|------|------|----------|
| 意图理解 | 语义 | LLM（已有 QueryFrame 路径） |
| 证据条数够不够 | 结构 | 规则（计数 + 阈值） |
| 有没有目标对象 | 结构 | 规则（Entity 匹配） |
| 多候选对象冲突 | 结构 | 规则（同义词检测） |
| 证据质量够不够 | 语义 | LLM（仅在规则判定"有疑问"时触发） |
| 知识缺口识别 | 语义 | LLM（仅在结果不充分时触发） |
| 推荐答案策略 | 语义 | LLM（基于上述判断综合输出） |

**执行链路**：
```
查询 → 规则判断（零延迟）
  → 判定"充足且明确" → 直接返回，不调 LLM
  → 判定"有疑问" → 调 LLM 做语义判断
  → 组装 ContextPack 返回
```

**为什么**：每个查询都调 LLM 的延迟和成本不可接受（路线 1）。纯规则又达不到"有经验工程师助理"的判断质量（路线 3）。规则先做快速过滤，大部分明确查询零 LLM 开销；只有真正需要语义判断时才付费。
