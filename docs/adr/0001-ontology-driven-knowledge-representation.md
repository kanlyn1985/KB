# 知识表示采用 Ontology 驱动而非文档切片

我们放弃"文档→EvidenceBlock→Fact→RetrievalCard"的切片检索架构，改为"文档→LLM萃取→Ontology(Entity+Attribute+Relation)"的知识图谱架构。知识一旦萃取进本体，与原文档解耦，查询时遍历本体而非匹配文本。

**为什么**：文档切片路线的根本缺陷是"找文本"而非"找知识"。同一概念（如 DCDC输出纹波）分散在多篇文档里，切片检索无法跨文档归并；而本体通过 Entity 唯一性规则自然合并多源信息，查询返回的是结构化数据（值=30mVpp，条件=额定负载）而非一段文字。

**代价**：每篇文档接入需要 LLM 萃取（成本和延迟）；Entity 唯一性和合并逻辑复杂；放弃了向量相似度检索的能力（但不做语义模糊搜索是这个系统的设计选择）。
